## Ancestor/descendant cross-hierarchy edges (2026-10-24)

Four divergences from elk-go v0.2.0 `internal/layered/compound.go` and
`transferrer.go` for edges between a compound node and its own descendant:

- `externalDummyForBoundary` takes the side of a reused compound endpoint from
  `compoundPortNetFlow` over all of the port's edges. Rust hard-coded output
  for a reused source (and input for a reused target), so an
  ancestor-to-child edge left through the south side instead of entering from
  the north. Ported as `compound_port_net_flow`; the dummy also receives the
  boundary port's own side, which counts once the compound's sides are fixed.
- `CompoundGraphPreprocessor.Process` splits edges in arena allocation order,
  i.e. the breadth-first containment import order recorded as edge model
  order, not wire order. The first boundary dummy fixes the compound's port
  sides, so the order decides later endpoints' sides.
- `moveCrossHierarchyLabels` puts CENTER labels on
  `shallowestHierarchySegment`. Without a central segment (ancestor endpoint)
  that is the boundary segment inside the ancestor's child graph; Rust only
  looked in the endpoint LCA graph and silently dropped the label dummy.
- `Transferrer.applyEdge`/`edgeLayoutOffsets` publish such edges relative to
  the ancestor node and, for an ancestor source, walk the hierarchical offset
  from the ancestor's own graph (never meeting its origin). Ported as
  `hierarchy_edge_offset_x` and the corrected walk in
